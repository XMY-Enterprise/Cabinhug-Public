# 数据说明与合规声明

本文说明 Cabinhug 公开仓库里随代码提供了哪些数据、系统运行时会产生和处理哪些数据、哪些数据需要部署方自行准备并自行承担合规责任。仓库本身不包含任何真实用户、真实车辆或真实凭证的数据。

## 仓库里的数据

| 位置 | 内容 | 来源与性质 |
|---|---|---|
| `data/kb-src/` | 购车费用与金融规则的说明文档 | 项目自行编写的规则口径（购置税、保险、贷款的计算规则），不含算好的金额；可直接上传到知识库 `car-catalog` |
| `data/memories/` | 一条行程记忆样例 | 虚构人物与虚构行程，用于演示记忆的数据形状 |
| `mocks/dealer/data/` | 车型与配置价格、门店 | 车型配置与指导价整理自厂商公开资料；门店名称、地址、坐标为虚构 |
| `mocks/cabin/data/` | 各车型舒适域能力表 | 虚构的能力矩阵，用于模拟座舱控制 |
| `mocks/repair/data/` | 维修站、报价、维修历史 | 全部虚构，VIN 以 `DEM0` 开头 |
| `mocks/insurance/data/` | 保单 | 全部虚构，保险公司名称标注为「模拟」 |
| `evals/*/cases.jsonl` | 评测题与判定 | 项目自行编写的合成用例，不含真实对话 |
| 各包 `test/` 下的夹具 | 单元测试数据 | 合成值。测试里出现的手机号、邮箱、VIN 均为假值 |

不在仓库里、但代码会读取的目录：

| 位置 | 内容 | 说明 |
|---|---|---|
| `data/kb-md/` | 车辆说明书、维修保养手册、车型手册转换成的 markdown | 由部署方用 `kb:convert` 从自己的 PDF 生成，`.gitignore` 排除 |
| `data/mem0-*.db` | 本地开发时 Mem0 的历史与向量库 | 运行时产生，`.gitignore` 排除 |

## 系统运行时处理的数据

按存储位置划分，系统涉及以下六类数据。它们全部产生于部署方自己的环境，仓库不提供样本之外的任何真实记录。

| 类别 | 内容 | 存储 | 保留策略 |
|---|---|---|---|
| 短期任务状态 | 一轮对话内的图状态与会话 | 编排层检查点、pi 会话 | 硬过期 |
| 情景记忆 | 去过哪里、做过什么 | Mem0（向量库在 PostgreSQL pgvector） | 指数衰减 |
| 偏好 | 座舱偏好、路线偏好 | Mem0 | 慢衰减 |
| 车辆档案 | VIN、保养与维修记录、成员与联系人 | PostgreSQL | 不衰减，事件驱动更新 |
| 环境缓存 | 天气、充电价格等 | Redis | TTL 过期 |
| 用车数据 | 里程、充电、路况的时序流水，以及聚合后的用车画像 | PostgreSQL `trips` 表；画像写入 Mem0 | 原始流水按部署方策略保留 |

其中会涉及个人信息的字段与处理方式：

- 联系人电话：工具层只向模型返回尾号，完整号码只在内部通道传给预约后端，不进入图状态与模型上下文。
- 输出脱敏：模型回复在返回终端前经过个人信息脱敏（手机号、身份证号、邮箱等），实现位于 `enterprise/backend/shared/guardrails/src/output/`。
- 审计：内容审核与权限门的裁决落库留痕，采样策略由配置决定。
- 定位与轨迹：出行规划与用车数据依赖终端上报的位置，仅在部署方自己的服务端处理。

系统不采集、不上传任何车辆控制信号。终端的能力白名单不包含车辆控制，这是代码层面的约束，见根 README 的「安全边界」。

## 需要部署方自行决定的数据

以下数据不随仓库提供。部署方在私有化部署时自行准备，并对其来源与授权负责。

### 知识库语料

RAG 使用三个数据集，隔离由代码在调用层强制，按消费方划分：

| 数据集 | 消费方 | 适合放入的资料 |
|---|---|---|
| `vehicle-manuals` | 用车助手 | 用户手册、导航娱乐系统手册、功能操作说明 |
| `repair-kb` | 售后服务 | 保修及保养手册、故障码表、技术通告、维修工艺 |
| `car-catalog` | 购车顾问 | 车型手册与配置参数、选装表、价格表 |

厂商的说明书、维修手册与价格表通常受版权保护。将其导入知识库前，确认你有权在自己的部署范围内使用这些资料。代码中的 `provenance` 字段用于标注资料是公开来源还是模拟数据，导入时按实际情况设置，不要给模拟数据标注为公开来源，也不要相反。

导入命令：

```bash
corepack pnpm kb:convert <PDF...>
corepack pnpm kb:upload <数据集> <文件...>
```

### 演示数据

`corepack pnpm demo:seed` 会向数据库写入两辆演示车辆及其保养、维修与行程记录。这些记录可以被识别和清理：VIN 以 `DEMO` 开头，行程 id 以 `demo-trip-` 开头，记忆带 `provenance: "simulated"` 标记。`corepack pnpm demo:seed --reset` 只删除带这些前缀的记录，不影响真实数据。

### 用户数据

用户账号、车辆档案、对话记录、用车数据均由部署方的系统产生并存储。部署方需要按所在地区的法律要求处理用户告知、同意、访问与删除请求。仓库提供的是处理这些数据的代码，不提供合规流程。

## 第三方服务

启用真实外部服务时，用户输入会发送到对应的服务提供方：LLM（DeepSeek / Qwen）、语音识别、内容审核（阿里云）、地图（高德）、知识库（RAGFlow）。每一项都可以不配置，此时系统以 Fake 或 Mock 方式运行，数据不出本机。各服务的作用与缺省行为见 [infra/external-dependencies.md](../infra/external-dependencies.md)。
