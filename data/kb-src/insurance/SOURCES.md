## 条款原件怎么取（**仓库里没有这个文件**）

第三方条款原件不进仓库（2026-09-16 决定，避免知识产权问题）：本目录的 `.gitignore` 排除 `*.pdf`，
转换产物所在的 `data/kb-md/` 与 `data/kb-figures/` 本来就在仓库根 `.gitignore` 里。
仓库里只留上表那一行——去哪下、哪天下的、sha256 是多少。重建两条命令：

```bash
curl -sSL -o "data/kb-src/insurance/中保协_行业示范_新能源商业险_2021-12_示范条款（试行）.pdf" \
  "https://car.tk.cn/offweb/img/page/areaInfo/doc/xnysyzstk.pdf"
corepack pnpm kb:convert "data/kb-src/insurance/中保协_行业示范_新能源商业险_2021-12_示范条款（试行）.pdf"
```

下载后先核对 sha256 与上表一致，再按"修正记录"列做那一处标题层级修正，然后
`corepack pnpm kb:replace insurance-kb data/kb-md/<产物>.md`。

## 主键段的写法

- 行业示范条款：险企段 `中保协`、渠道段 `行业示范`（D15）。
- 险企理赔指引（后续补）：`<险企>_<渠道>_<sku 或 通用>_<年份>_理赔指引.md`，渠道取 `直销 / 4S代销 / 品牌经纪 / 平台` 之一。
- 品牌薄层：文件名同时带品牌与车型别名（`Model3_ModelY`），`documentMatchesModel` 按文档名匹配车型限定——主键段只在本表里不在文件名里，检索限定就看不见它。

## 不入库的东西

- 任何险企的费率数字；"特斯拉合作险企"名单（特斯拉在华是保险经纪不是承保方，名单不公开也不稳定）。
- `mocks/insurance/data/policies.json` 的假保单（假保单与真条款是两回事）。
- 条款原文的摘要或改写——条款只允许标题层级修正，且记进本表"修正记录"列。

## ⚠️ 已知限制：行业级文档对"限定车型"的检索是隐形的

`probe:ragflow` 会把它报出来：

```
隐形：insurance-kb/[整理]行业_通用_理赔流程_2026_车险出险流程与材料时限.md
隐形：insurance-kb/中保协_行业示范_新能源商业险_2021-12_示范条款（试行）.md
```

`ownershipDual` 检索时会把 `vehicleModel` 传给 `ragflow_retrieve`（`ownership.ts:894`），
而 `documentMatchesModel` 按**文档名**匹配车型——这两份文档名里没有任何车型（它们本来就是行业级的），
于是限定车型时它们被过滤掉。这与迈锐宝那次是同一个形状：**表现不是报错，是"没有这款车的资料"，而那是假的**。

不能靠改名解决：给行业条款塞一个车型名就是假的，且与 D15 的主键段冲突（险企段 `中保协`、渠道段 `行业示范`）。
正确的修法在代码侧——检索 `insurance-kb` 时不要施加车型限定。M96-04 的边界禁止改代码，所以记为技术债，
去向见验收 M96-04 §7。
