> 验收在 M80-05。
>
> **一句话结论**：两遍该分开选——定位那一遍通义千问明显更准，描述那一遍 DeepSeek 明显更稳且快 2.5 倍。

- 数据集：`evals/vision-observe/cases.jsonl` 的 21 张（1 张真实仪表照 `tesla-01` + 20 张负样本）。

## 怎么读这四张表

1. **表一暴露的是 DeepSeek 的结构性短板**：bbox 平均 IoU 0.643。它按约 800×800 等效像素下采样，坐标精度上不去；词表越界的 23 条里全是「bbox 不是 0–1000 四元组」。定位那一遍不能换给它。
2. **表二把变量控住了**：检测那一遍固定 `qwen3-vl-flash`，两次运行拿到的是同一批框，差别只在"拿到这个 crop 之后怎么描述"。在这个条件下 DeepSeek 赢在**元素集合**（Jaccard 1.000 vs 0.500）与**警示灯状态**（4/4 vs 3/4），而这两项正是下游图标匹配要用的。
3. **表三是最要紧的一张**：同一批框下，qwen 在 12 张负样本上报出 28 次高置信警示灯，DeepSeek 报 5 次。误报在这条链路上比漏报更贵——车主拿着一张仪表照来问，答"你的胎压灯亮了"而其实没亮，是我们最不该犯的错。
4. **表四回答"端侧定位 + 云端描述"这个形态还差多少**：框够用（IoU 0.726、73 ms），名字全错但那不重要（名称只来自手册图标目录）；卡在负样本——20 张里 13 个误报框，集中在四张 App 截图上，与 M79-01 记的那条一样。

## 2026-09-10 追加 · 表五 · 端侧检测器当第一遍（M80-07）：YOLO + qwen vs YOLO + DeepSeek

> 第一遍换成 M79 训出来的 yolo11n（经训练服务 `/predict`，conf 0.25），两次运行的框**完全相同**，只换第二遍。
> 复跑：`corepack pnpm eval:vision-observe -- --via adapter --detect-provider yolo --model qwen3-vl-plus|deepseek-flash`。

| 指标 | YOLO + qwen3-vl-plus | YOLO + deepseek-flash | 谁更好 |
|---|---|---|---|
| 警示灯召回 V-R2 | 2/4 | 2/4 | 平（框是同一批：漏 `low_beam`、`auto_high_beam_standby`） |
| bbox 平均 IoU V-B1 | 0.711 | 0.711 | 平（同一批框） |
| 形状一致率 V-S1 | 2/2 | 1/2 | qwen（DeepSeek 把驻车灯的 `lamp` 说成 `other`） |
| 元素 Jaccard V-E1 | 0.500 | 1.000 | DeepSeek（qwen 把驻车灯的直线说成 `arrow_left / arrow_right`） |
| 颜色 / 代码定色 / 状态 | 2/2 全对 | 2/2 全对 | 平 |
| 负样本高置信警示灯 V-N1 | 1（20 张） | 1（20 张） | 平（都是 neg-16 那一个框） |
| 不可解析 | 0 / 21 | 0 / 21 | 平（YOLO 不会 JSON 截断） |
| cut_off_sides V-Q1 | 0/1 | 0/1 | 平（YOLO 不知道裁边，如实留空） |
| tesla-01 整张耗时 | 2861 ms | 818 ms | DeepSeek（2.5×） |
| 有框的 5 张上描述 p50 | 2840 ms | 817 ms | DeepSeek |

### 怎么读

1. **瓶颈在 YOLO，不在第二遍**：两条线的召回都被钉在 2/4，因为框只有那两个。第二遍换谁都补不回漏掉的近光灯与自适应远光。
2. **第二遍两家在这 2 个框上打平**：各错一项（qwen 错元素、DeepSeek 错形状），颜色 / 状态全对。样本只有 2 个项，分不出高下，只能说"没有谁明显更差"。
3. **负样本上 YOLO 先把大部分误报挡在了外面**：20 张只出 13 个框，进第二遍后高置信警示灯只剩 1 个——对比云端 qwen 定位那条线的 28 / 5。这是端侧定位的真实好处：不该看的根本不送去看。
4. **速度**：整张从云端定位的 27 s 掉到 50–80 ms（无框时）、1.3–3.1 s（有框时）。DeepSeek 描述仍比 qwen 快 2.5 倍。

### 结论

"YOLO + qwen"与"YOLO + DeepSeek"**分不出胜负**——分母太小（2 个项）。真正的结论是：**要走端侧定位这条路，先把 YOLO 的召回从 2/4 提上去**（`low_beam` 在合成集上 mAP50 只有 0.15，是训练数据的事）；第二遍选谁，按前面表二（同一批云端框、12 张负样本）的证据，DeepSeek 更稳更快。
